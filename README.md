# GB Racer

A pseudo-3D racing game for the original Game Boy (DMG), written in C and hand-written SM83
assembly with the GBDK-2020 toolchain.  128 KB ROM, MBC1 + 8 KB battery-backed save RAM, and a
Super Game Boy border.

Three tracks (OVAL, CANYON, ALPINE), three race lengths (3/5/10 laps), three difficulty levels,
two racing rivals plus random traffic, lap times and per-track/level/length records.

Current release: tag **v1.3** (a Super Game Boy border); the full PyBoy suite (`make test`)
passes.  v1.2 brought bends you can see coming, an honest corner sign and a fairer ALPINE.

## Controls

| Title screen | Race |
|---|---|
| UP / DOWN: track | LEFT / RIGHT: steer |
| LEFT / RIGHT: laps | A or UP: accelerate |
| SELECT: difficulty | B or DOWN: brake (works while accelerating) |
| START: start race | START: pause menu |

While paused, UP / DOWN select RESUME, RESTART, QUIT or SOUND ON/OFF; A or START activates the
item and B resumes.  SOUND mutes music and effects for the rest of the session (it is runtime only,
not saved).

The brake wins over the throttle, so you can hold A and tap B to slow for a bend.
Difficulty also changes the car, not just the AI: the corner push is 0.75x on EASY,
1x on NORMAL and 1.25x on HARD (on top of the per-lap increase). Off road the speed is
capped at 8 and steering drops to 1/16; the centrifugal push is disabled there, so a
mistake costs time without throwing you further out.

The car has weight. Steering asks for a sideways rate and the tyres take a couple of
frames to build it up, so the car keeps sliding for a moment after you let go and
counter-steers into a slide rather than snapping to the road. Holding a direction
makes the car turn harder the longer you hold it. Coasting slows you more the faster
you go, and a climb bleeds speed off while a descent gives it back.

You see a bend coming before you reach it.  The road is drawn as two bends: the one the car
is in, from the car up to where the next section starts, and the next one beyond that.  That
join comes down the screen at the road's own speed, so a bend appears on the horizon and
arrives at the car, and the car feels it from the moment it gets there (eased in over about
11 frames).  The road is drawn in blocks of 8 lines, and the block the join is passing
through is a blend of the two bends, so the far road sweeps round smoothly instead of
jumping a block at a time.  Before this, the whole road used one curve: a bend curled the road under the car
all at once, with no warning, and the car seemed to be pushed off a road that bent around it.
`tools/phasecheck.py` checks that a bend is never felt before it reaches the car on screen and
that the picture and the push agree.

The sky sign warns of a sharp bend ahead and flashes when you are too fast for it: when its
push, on this lap and level, would beat the steering at full lock.  (v1.1 flashed above fixed
speeds that ignored the lap and level, so by lap 5 it called a hairpin safe at a speed that
threw the car off.)  ALPINE's bends are a sixth gentler than in v1.1, where a driver with a
person's reaction time left the road on nearly every one; it is still the hardest track, and
flat out still loses clearly to braking there.

## Building

Requires [GBDK-2020](https://github.com/gbdk-2020/gbdk-2020/releases) and Python 3 (the asset
generators run during the build).  Tested with GBDK **4.5.0** on macOS arm64.
```sh
# GBDK defaults to $HOME/vendor/gbdk; override with make GBDK=/path/to/gbdk
make                          # -> build/racer.gb
make variants                 # -> build/prof_*.gb (PROFILE builds used by the tests)
```

`src/road_data.c`, `src/pat_rows*.s`, `src/sprite_*.c`, `src/hud_*.c` and `src/audio_data.c` are
generated by `tools/gen_*.py` and checked in; `make` regenerates them when the generators change.

### Super Game Boy border

On a Super Game Boy the screen sits in a race circuit: chequered flags, the title, red and white
kerbs round the screen, grass and a starting grid.  On a plain Game Boy nothing changes.

```sh
make border     # regenerate src/border_data.c after changing tools/sgb/racer_art.py
```

`tools/sgb/racer_art.py` draws the art (tile-aligned, 56 tiles, one palette);
[GB-SGB-Tooling](https://github.com/Zapskii/GB-SGB-Tooling)'s `mkborder.py` packs it (expected at
`~/GB-SGB-Tooling`, override with `SGB_TOOLING=`) and png2asset converts it into ROM bank 4.
The output is committed, so plain `make` doesn't need the tooling.  `src/sgb_border.c`/`.h` are
that repo's fixed copy of GBDK's transfer code, unchanged; `src/sgb_boot.c` sends the border
and a greyscale game palette at boot, before any graphics are loaded (the transfer overwrites
VRAM), and `-Wm-ys` sets the header's SGB flag.  Check it with the tooling's two tests:

```sh
python3 ~/GB-SGB-Tooling/sgb_border_test.py build/racer.gb tools/sgb/border.png src/border_data.c   # PyBoy: the bytes
python3 ~/GB-SGB-Tooling/gearboy_check.py build/racer.gb tools/sgb/border.png                       # Gearboy: the pixels
```

Not yet tried on a real Super Game Boy.

## Testing

The checks run the real ROM in [PyBoy](https://github.com/Baekalfen/PyBoy) (tested with 2.8.1)
and read symbols from the `.noi` file that `lcc -Wl-j` writes next to each ROM.  Use a venv so
the system Python stays clean; `make` auto-detects `.venv/bin/python` when it exists.

```sh
python3 -m venv .venv
.venv/bin/pip install pyboy pillow

make check     # layout, both table builders, and the fast regressions
make test      # everything above plus races, sprites, audio, save, hills (a few minutes)
```

If the venv lives elsewhere: `make check PYTHON=/path/to/python`.

The regression checks added by the upgrade are `tools/brakecheck.py` (A+B must slow the car),
`tools/levelcheck.py` (EASY/NORMAL/HARD scale the push), `tools/offroadcheck.py` (the push is
gone once the grass cap applies), `tools/steercheck.py` (the steering ramp survives a short
release), `tools/phasecheck.py` (a bend reaches the car on screen before the car feels it, and
the picture and the push agree), `tools/flickercheck.py` (a rival hidden by the OAM multiplexer must not collide),
`tools/audiostatecheck.py` (title/pause must pass `g_hits`, not 0, to `audio_update`) and
`tools/pausecheck.py` (pause menu, sound mute, restart and quit).  The older tools each cover
one subsystem; many support `--break <name>` to prove the check can fail on a deliberately
wrong model.  `audiocheck` measures engine steps 1-7; step 0's expected subharmonic is below
the ACF band and is covered by the standstill check.

`tools/humancheck.py build/prof_race.gb [delay ...]` is a report, not a pass/fail check: a bot
that drives like a person (from the car's position and drift on screen, with a reaction delay,
braking when the sign flashes) and prints, per track, the share of time on the grass, the mean
speed, how often the car left the road and for how long.  Use it to judge a handling or track
change on how it treats a player.

## Layout

```
src/main.c      main loop, VBlank/timer/HBlank setup, both table builders
src/raster.s    HBlank ISR (SCX/BGP per line) + asm SCX table builder
src/draw.s      rival projection and OAM writes
src/game.c      physics, track segments, laps, records
src/flow.c      title -> countdown -> race -> finish -> results; pause menu
src/sprites.c   rivals, traffic, AI, posts, warning sign, per-line OAM budget
src/hud.c       race HUD, banners and the pause menu (bank 0)
src/menus.c     title/results pages (bank 1, reached via SWITCH_ROM_MBC1(1))
src/audio.c     music sequencer, engine/crash/gravel, jingles, mute
src/sram.c      battery save (magic + version + checksum)
src/boot.c      start-up video: SGB border, road/sky tiles, map, road tables (bank 1)
src/sgb_boot.c  Super Game Boy border and palette (bank 4); includes src/sgb_border.c
tools/          asset generators and PyBoy checks
bench/          cycle benchmark (development artifact; see bench/Makefile)
```

### Frame pipeline

1. VBlank IRQ re-anchors the timer, swaps the double-buffered SCX/BGP pages, resets
   `SCX/SCY/BGP`.
2. Timer IRQ enables/disables the HBlank STAT ISR at roughly lines 43 and 131.
3. The HBlank ISR writes `SCX` and `BGP` for every road line (49 M-cycles/line).
4. Main loop: `hud_update` (VBlank), `game_update`, table build, `sprites_update`,
   `audio_update`, `flow_after_update`.

### Memory map

- Bank 0: code and runtime data (`src/sram.c` is in bank 1 via `BANKED` calls, made only with the road ISR off).  Must end below `$4000` (`tools/romcheck.py`), with at least
  64 bytes headroom; the current build has 149 bytes free.  GBDK's SGB routines
  (`sgb_check`, `sgb_transfer`, `set_bkg_tiles`, `fill_bkg_rect`) are library code and link here.
- Bank 1: boot-time data (road/sprite/font), the start-up code that copies it (`src/boot.c`),
  the full-screen menu code (`src/menus.c`) and the CANYON palette rows at `$6000`.
- Banks 2/3: OVAL/ALPINE palette rows at `$6000`.
- Bank 4: the Super Game Boy border (`src/border_data.c`) and its transfer code; banks 5-7 are free.
- WRAM `$D000-$D3FF`: four page-aligned 256-byte road tables (SCX/BGP double buffers;
  `tools/romcheck.py` also checks `_DATA`/`_BSS` stay below `$D000`).

Bank 0 is tight, so the build uses SDCC's `--opt-code-size` (`-Wf--opt-code-size` in the
Makefile); without it the PROFILE builds spill into bank 1 and won't boot.  The full-screen
pages live in bank 1 (`src/menus.c`); call `SWITCH_ROM_MBC1(1)` before drawing them and let
`road_set_track()` map the track palette bank again when a race starts.  The pause menu stays
in bank 0 because the race palette bank is still mapped while paused.

### Save format

`$A000` battery RAM, 61 bytes: magic `GR`, version 1, title selections, 27 little-endian
`uint16` best race times (`[level][track][laps]`), checksum `(sum bytes 2..59) ^ 0xA5`.
Invalid magic/version/checksum/selection means "no records".

## Known limitations

- The cycle benchmark under `bench/` includes `src/main.c` and links the whole game, which no
  longer fits bank 0 with GBDK 4.5.  It is not built by `make`; making it work needs the table
  builders moved out of `main.c`.
- `tools/crosscheck.py` reports a 1-2 px difference between the C and asm table builders by
  design (different rounding); `tools/modelcheck.py` checks the asm builder bit-exactly.
